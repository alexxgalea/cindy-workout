# U0: iOS UI Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the `subagent-driven-development` skill (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** give the iPhone app the rest of Android's design vocabulary (the `ic_*` icons, the row and button components of `CindyViews.kt`, and the bottom sheet of `CindySheet.kt`), and put its first consumers on it: Help's rows and icons, and the stop, skip and discard questions.

**Architecture:** the icons are generated from the Android vector drawables into SVG imagesets, and a CindyCore test holds the two in step. The components are SwiftUI views in one new file, `CindyViews.swift`, styled only through `Palette` and `CindyType`. The sheet is an overlay that a screen attaches at its root (`.cindySheet(…)`), not a system sheet, so it can sit square and flush over the camera as Android's does.

**Tech Stack:** SwiftUI (iOS 17.0), CindyCore (XCTest on Linux), Python 3 for the generator, XcodeGen, XCUITest.

**Spec:** `ios/ui-parity/PLAN.md` (decisions and global constraints) and `docs/adr/0003-ios-follows-android-ui.md`.

**Branch:** `ios-ui-u0-foundation` from `origin/main`. The pull request targets `main`.

## Global Constraints

Everything in the master plan's global constraints, in particular:
- iOS 17.0 floor. No `ForEach(subviews:)` or `Group(subviews:)`.
- No blur and no system materials. Colours only from `Palette`, type only from `CindyType`.
- Words verbatim from the Kotlin on `origin/main`.
- No attribution lines. No phase ids in code or comments.

## Verification commands

- **Core tests.** On a Mac: `swift test --package-path ios/CindyCore`. On Linux or in a cloud session: `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble swift test --package-path ios/CindyCore`. Add `--filter <TestClass>` to run one class.
- **App tests.** On a Mac: `cd ios && xcodegen generate && cd .. && xcodebuild test -project ios/CindyTracker.xcodeproj -scheme CindyTracker -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO`. In a cloud session, push and read the pull request's `Build Cindy iOS` check (see `CLAUDE.md`); open the pull request as a draft at the end of Task 1 so every later push is tested.

## Review Focus

- A dismissal that is not a button (a tap on the dim, a swipe down, the VoiceOver escape) on the stop question must leave the clock running, as KEEP GOING does. Test in Task 3.
- With the sheet up, the camera's controls must be absent from the accessibility tree. Test in Task 3.
- At `accessibility-XXXL` the stop question's END must stay hittable. Test in Task 3.
- An SVG that Xcode's asset compiler draws blank, or fills black where Android leaves the path unfilled (SVG's default fill is black, Android's is none). Pinned by the generator's explicit `fill="none"` and checked on Help's captures in Task 4.
- A sheet presented from inside a system sheet (the session page is still a `.sheet` until U2) must cover only that sheet's area and still dismiss. This is checked by the existing discard UI test in Task 3.

- [ ] **Step 3: Write `tools/ios_icons.py`** (no arguments, run from the repository root, rewrites `Icons/` from scratch each time). The mapping, which is the part the test does not determine:
  - `<svg xmlns="http://www.w3.org/2000/svg" width="{android:width less "dp"}" height="…" viewBox="0 0 {viewportWidth} {viewportHeight}">`.

```swift
struct SheetButton {
    let title: String
    var tint: Color = Palette.label        // only the secondary uses it
    let action: () -> Void
}

extension View {
    /// Attach at the root of a screen. `onDismiss` runs once, however the sheet closes.
    func cindySheet<Content: View>(isPresented: Binding<Bool>, title: String, subtitle: String? = nil,
                                   primary: SheetButton, secondary: SheetButton? = nil,
                                   secondaryDismisses: Bool = true, onDismiss: @escaping () -> Void = {},
                                   @ViewBuilder content: @escaping () -> Content) -> some View
    // and the same without `content`, for a question that is only words
}

struct SheetToggle: View { init(_ label: String, isOn: Binding<Bool>) }
struct SheetSlider: View { init(_ label: String, value: Binding<Double>, onSettled: @escaping (Double) -> Void = { _ in }) }
```

- Accessibility identifiers: the sheet is `cindySheet`, its buttons `sheetPrimary` and `sheetSecondary`.

What the sheet does, from `CindySheet.kt` and `Theme.Cindy.Sheet`:
- **Layout.** A full-screen `Palette.scrim`. Over it, the sheet sits flush to the bottom, full width, with **square corners**. Its background is a vertical gradient: `specular` at 0, `sheetMid` at 0.003, `sheetEnd` at 1. Padding is 12 top, 20 sides, and 28 plus the bottom safe area underneath. Inside, from the top:
  - a handle 38×4 in `Color(argb: 0x33FFFFFF)` with radius 2, and 20 below it;
  - the title in `.title2`, with the `.isHeader` trait;
  - the subtitle in `.callout`, 5 below;
  - the content in a `ScrollView` capped at 60% of the screen's height, 18 below;
  - the actions in an `HStack(spacing: 10)`, 18 below: the secondary first, in `CindyGlassButtonStyle(tint:)`, then the primary in `CindyPrimaryButtonStyle`, which takes the rest of the width.
- **Motion.** The sheet slides up from below the screen in 0.3 s on `.timingCurve(0.22, 1, 0.36, 1, duration: 0.3)` (Android's `decelerate_quint`), and the dim fades in with it. Leaving reverses both.
- **Buttons.** The primary runs its action and then closes. The secondary runs its action and closes unless `secondaryDismisses` is false.
- **Other ways out.** A tap on the dim, a downward drag past 100 pt (or a predicted end past 200 pt), or the accessibility escape action closes the sheet without running either button. Each of these is Android's back gesture.
- **`onDismiss`** runs exactly once per close, after any button action.
- **Beneath.** While the sheet is up, the content it is attached to gets `.accessibilityHidden(true)` and `.allowsHitTesting(false)`.
- **Keyboard.** The sheet respects the keyboard's safe area. Never write `.ignoresSafeArea(.keyboard)`.
- **`SheetToggle`** (Android's `toggle`): a `glassCard` row at least 52 high, 20 above it, with the label in `.callout` in `label`, a 47×28 switch on the right, and the accessibility value "on"/"off". **`SheetSlider`** (Android's `slider`): a `glassCard`, 14 above it, with the label in `.callout` and its percentage in `.headline` on one line, a slider from 0 to 1 below, and `onSettled` when the drag ends. Both are built here and first used in U5.
