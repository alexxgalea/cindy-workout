# U2: session page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the `subagent-driven-development` skill (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the iPhone app's session page (the page that opens when a workout ends, and when a saved session is reopened) has the Android page's shape: full-screen, closed with DONE, its cards in the order and look of `activity_results.xml`, its words verbatim, and its question a Cindy sheet.

**Architecture:** the page's decisions already live in CindyCore (`ResultsPageBuilder`, `ResultsModel`, the four chart models), so this phase changes what SwiftUI draws and, where a word is drawn by the view and not held by the model, moves it into CindyCore with a test that reads it off the Kotlin. The cards are built from U0's `InsetGroup`, `ValueRow`, `NavRow`, `ChipRow`, `Medal`, `BadgeDisc`, `ActionBar` and `glassCard`. They go in a new `ResultsCards.swift` and `ResultsHeart.swift`, so `ResultsView.swift` composes the page and no longer draws every card.

**Tech Stack:** SwiftUI (iOS 17.0), CindyCore (XCTest on Linux), XCUITest with `-CindyReplay`.

**Spec:** `ios/ui-parity/PLAN.md` (decisions and global constraints) and `docs/adr/0003-ios-follows-android-ui.md`. The Android sources, read on `origin/main` at `e9b405d`: `res/layout/activity_results.xml`, `ResultsActivity.kt` (`render`, `celebrate`, `sessionNumbers`, `roundTrack`, `renderMovements`, `renderLevel`, `liftedCard`, `compareCard`, `comparisonCardView`, `renderTimeline`, `renderHeartRate`, `heartFigures`, `zoneBlock`, `energy`, `explainHeelsFlat`), `StatTiles.kt` (`statTileGrid`, `movementCard`).

## Global Constraints

Everything in the master plan's global constraints, in particular:
- iOS 17.0 is the floor. No blur, no system materials. Colours only from `Palette`, type only from `CindyType` and `Manrope`, icons only from `CindyIcon`.
- Words are copied verbatim from the Kotlin. Nothing in code or comments names a phase.
- **`Ink`, `Color.accent`, `Color.dim`, `Color.warn`, `Chip`, `PrimaryButton` and `GhostButton` stay defined.** Progress, Account and the menu still use them. `Ink` lives in `ResultsCharts.swift`: this phase stops using it there and in `ResultsView.swift`, and keeps the enum, with a comment saying who still reads it.
- The chart models in CindyCore own the geometry and the touch, and are not changed. The views paint what they say.
- Progress (`ProgressScreen`) and the menu's sheets (`BodyWeightSheet`, `HeartRateDetailsSheet`, `StravaConsentSheet`) are other phases' and stay as they are; this page still presents them as it does today.
- The accessibility identifiers that `CindyTrackerUITests` uses keep working (`toast`, `stravaRow`), and a button keeps its word (`PROGRESS`, `DISCARD`, `DONE`).

## Verification commands

- **Core tests.** `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble swift test --package-path ios/CindyCore`, with `--filter <Class>` for one. If Docker is not running in a cloud session: `pkill -9 containerd; pkill -9 dockerd; rm -f /run/containerd/containerd.sock /var/run/docker.pid /var/run/docker.sock; dockerd &`.
- **Parse the app.** `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble sh -c 'for f in ios/CindyTracker/*.swift ios/CindyTrackerUITests/*.swift; do swiftc -parse $f || echo FAIL $f; done'`. Syntax only.
- **App tests.** Open the pull request as a draft after Task 1 and read `Build and test the app (macOS)` after pushes; a run takes about 22 minutes. Its log's last lines list every failed UI test with its assertion. A view hidden from accessibility stays in a UI test's queries, so VoiceOver's view of the page is not testable there and is owed on a phone.

## Review Focus

- **The largest Dynamic Type size.** At `accessibility-XXXL` the score does not clip, the tiles' figures shrink rather than wrap, and DONE can be scrolled to and hit. Test in Task 2.
- **A reopened session nested over another.** The COMPARED WITH card opens that session over the page it came from, and DONE returns to the first page, not to the camera. DISCARD there says "Session discarded" under it. Test in Task 3.
- **A record with no sets.** An older record has no rounds, movements, timeline or heart rate: the page shows the tiles, the level and the details and leaves no gap or empty card where the others would be. Pinned in CindyCore in Task 1, which already holds the page's sections.
- **The question closed without a button.** The dim, the escape gesture and a swipe down on the heels-flat question do what NOT NOW does: nothing is changed. By construction (the sheet's own rule); owed on a phone, because a session with heels flat cannot be replayed.
- **The page is the only thing a screen reader reaches.** The camera screen under the cover is out of the accessibility tree; the lifted card is one stop. Owed on a phone.
