# U6: Placement guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the `subagent-driven-development` skill (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the placement guide the START button opens before the first setup check is a Cindy sheet over the live camera preview, as on Android, with Android's words, its diagram card, its three facts drawn with the `ic_*` marks, its toggle and its two buttons, and with Android's rule for what each way out of it does.

**Architecture:** `showPlacementGuide` in `MainActivity.kt` builds a `CindySheet` (title, subtitle, the `PlacementGuideView` in a glass card 200 high, `placementFacts()`, a toggle, START SETUP and NOT NOW). iOS already has the sheet (`cindySheet`, `SheetToggle`, `SheetButton`) and the diagram (`PlacementDiagram`, a faithful port of `PlacementGuideView.kt`; checked line by line against it for this plan, nothing in the drawing differs). This phase replaces the system `.sheet` and its `PlacementGuideView` with a modifier that owns the sheet, and redraws `PlacementFactRows` as `placementFacts()` draws them. The facts model in CindyCore trades SF Symbol names for Android's drawable names, and the guide's own words move into CindyCore with tests that read them off the Kotlin.

**Tech Stack:** SwiftUI (iOS 17.0), CindyCore (XCTest on Linux), XCUITest with `-CindyReplay`.

**Spec:** `ios/ui-parity/PLAN.md` (decisions and global constraints) and `docs/adr/0003-ios-follows-android-ui.md`. Android sources, read on `origin/main`: `MainActivity.kt` (`showPlacementGuide`), `PlacementGuideView.kt`, `PlacementFacts.kt`, `CindySheet.kt` (`toggle`, `actions`), `res/drawable/glass_card_small.xml`.

## Global Constraints

Everything in the master plan's global constraints, in particular:
- iOS 17.0 is the floor. No blur, no system materials. Colours only from `Palette`, type only from `CindyType`/`Manrope`, icons only from `CindyIcon`.
- Words are copied verbatim from the Kotlin: `Where to stand`, `The one thing you have to get right before the camera can help.`, `Don't show this again`, `START SETUP`, `NOT NOW`.
- Nothing in code or comments names a phase.
- **`ContentView.swift` is touched only where the placement is presented.** U5 edits the menu's sheets in parallel; the two pull requests must not collide. `ProfileSheets`, `VoiceSheet`, `MusicSheet`, `HeartRateSheet`, `ReminderSheet`, `StravaSheets` and `AccountScreen` are not touched.
- `CindyViews.swift` is not edited (master plan): a new component goes in a new file.
- The accessibility identifiers `CindyTrackerUITests` uses keep working; `testThePlacementGuideComesFirstAndCanBeTurnedOff` looks for `CONTINUE` and `Where to put the phone`, which go, so it changes in the same commit.
- `Onboarding.keyPlacementSeen` (`placement_guide_dismissed`) is an athlete's existing choice and keeps its name.
- **UI-test lessons from U2–U4:** find a control by identifier or exact label, never a shared fragment (the sheet's buttons are `sheetPrimary`/`sheetSecondary`; the controls beneath can share a label and stay in the query); a bare trailing closure whose body is an `if` can be taken for `onDismiss`, so name `content:`; `Text(verbatim:)` for ints; a launch argument such as `-placement_guide_dismissed NO` shadows the stored value for that launch only.

## Review Focus

- **The guide must not stop the camera or the workout.** It is an overlay of `ContentView`, not a cover, so `onDisappear` does not run; the presentation must stay an overlay. Test: the HUD is still there and idle after NOT NOW (Task 3); that nothing is torn down is by construction and owed on a phone.
- **A dismissal that is not a button.** The dim, a swipe down and the escape gesture do what NOT NOW does: nothing starts, nothing is kept, the guide comes back at the next START. Android keeps "Don't show this again" only from START SETUP, so a toggle left on and then dismissed is not kept. Test in Task 3.
- **The largest Dynamic Type size.** START SETUP stays on screen and hittable at `accessibility-XXXL` (the sheet's words and content scroll inside 60% of the height). Test in Task 3.
- **VoiceOver under the sheet.** The camera screen leaves the accessibility tree while the guide is up (the sheet's rule, and `screenIsCovered` gains the guide). Owed on a phone.
- **The smallest phone (375×667).** The 200-high diagram, three facts, toggle and buttons exceed the 60% cap, so the body scrolls and the buttons stay pinned. Owed on a phone.

### Task 2: The guide as a Cindy sheet

**Files:**
- Modify: `ios/CindyTracker/PlacementDiagram.swift` (`PlacementFactRows`), `ios/CindyTracker/ContentView.swift` (placement only)
- Rewrite: `ios/CindyTracker/PlacementGuideView.swift`
- Test: `ios/CindyTrackerUITests/CindyTrackerUITests.swift`

**Interfaces:**
- Consumes: `cindySheet(isPresented:title:subtitle:primary:secondary:content:)`, `SheetButton`, `SheetToggle`, `PlacementFacts`, `PlacementWords`, `CindyIcon`, `Palette`, `.cindy(_:colour:)`, `glassCard(radius:)`.
- Produces: `extension View { func placementGuide(isPresented: Binding<Bool>, onStart: @escaping () -> Void) -> some View }`.

What Android draws:
- **Sheet.** Title and subtitle from `PlacementWords`; content in order: the diagram card, the facts, the toggle; primary `START SETUP`, secondary `NOT NOW`.
- **Diagram card.** `PlacementDiagram` 200 high, padding 14 above, 12 either side, 8 below, `glass_card_small` (radius 18, so `glassCard(radius: 18)`).
- **Facts** (`PlacementFactRows`, shared with the first-launch pages, as in Kotlin): 18 above the first row and 13 above each other; per row a 17×17 `CindyIcon` 2 below the row's top, tinted `Palette.labelTertiary` (`Palette.stateCaution` for the `warning` fact), 11 before the text in `.callout` `Palette.labelBody`; the icon is hidden from VoiceOver. `PlacementFactRows` gains the 18 above its first row, and `TutorialScreen`'s `padding(.horizontal, 4)` wrapper is left as it is.
- **Toggle.** `SheetToggle(PlacementWords.dontShowAgain, isOn:)`, off at each presentation.
- **What each way out does.** START SETUP: if the toggle is on, write `Onboarding.keyPlacementSeen`, then `onStart()`. NOT NOW, the dim, a swipe down, the escape gesture: nothing, and the toggle is not kept.
- **The modifier owns** `@State dontShowAgain` and `@AppStorage(Onboarding.keyPlacementSeen)`; it resets the toggle when the sheet closes.
- **`ContentView`.** `.sheet(isPresented: $showPlacement) { … }` becomes `.placementGuide(isPresented: $showPlacement) { workout.enterSetup() }`; `screenIsCovered` gains `showPlacement`. `start()` and the `placementSeen` property stay.
