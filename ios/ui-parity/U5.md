# U5: The Menu's Sheets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the `subagent-driven-development` skill (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every sheet the menu opens, and the name sheet and photo dialog of the You screen, is a Cindy sheet with Android's content and buttons, in place of a system `Form` sheet with Save and Cancel, an `.alert` or a `confirmationDialog`.

**Architecture:** the decisions and words are in CindyCore already (`MovementsForm`, `BodyWeightForm`, `HeartRateDetailsForm`, `NameForm`, `PhotoSheet`, `VoiceForm`, `LanguageGroupModel`, `MusicFlow`, `ReminderPlan`, `HeartRateSheets`, `HeartRateAccess`, `StravaConsent`, `StravaSheet`). This phase changes what SwiftUI draws. U0's `CindySheet` is split into a presenter (the dim, the slide, the drag, the escape gesture, the isolation of what is beneath) and a panel (title, line, scrolling content, the two buttons), so that a sheet is a view that builds its own panel and is presented by item. A few components the sheets share (a note, a choice group, a field) go in one new file, `SheetKit.swift`.

**Tech Stack:** SwiftUI (iOS 17.0), CindyCore (XCTest on Linux), XCUITest with `-CindyReplay`.

**Spec:** `ios/ui-parity/PLAN.md` (decisions 4 and 6, global constraints, review focus) and `docs/adr/0003-ios-follows-android-ui.md`. The Android sources, read on `origin/main`: `MenuActivity.kt` (`chooseVoice`, `chooseMusic`, `chooseHeartRate*`, `openScanSheet`, `chooseReminder`, `notificationsOff`, `openStravaSheet`), `Dialogs.kt` (`chooseMovements`, `askBodyWeight`, `askHeartRateDetails`, `sheetNote`, `choiceGroup`), `AccountActivity.kt` (`choosePhoto`, `askName`), `CindySheet.kt` (`toggle`, `slider`, `actions`), `LanguageGroup.kt`, `StravaConsent.kt`.

## Global Constraints

Everything in the master plan's global constraints, in particular:
- iOS 17.0 is the floor. No blur, no system materials, no `Form`, `List`, `.alert`, `confirmationDialog` or `.presentationDetents` in the files this phase owns. Colours only from `Palette`, type only from `CindyType` and `Manrope`, icons only from `CindyIcon`.
- **Words are Android's where Android has them; where the platform differs, the iOS words the CindyCore models already hold stay** (iOS cannot fetch a voice, has no location prompt for Bluetooth, and its heart-rate permission has its own sheet). Words a view draws itself and Android has verbatim are held in `SheetWords` against the Kotlin.
- **The pickers stay the system's:** `PhotosPicker`, `fileImporter`, the time `DatePicker`, the permission prompts and Settings.
- `Ink`, `Color.accent`, `Color.dim`, `Color.warn`, `Chip`, `PrimaryButton` and `GhostButton` stay defined (U7 deletes them); this phase stops using them in its files.
- The models in CindyCore are not changed except for `SheetWords`. A sheet's save, refusal and permission rules are the model's.
- **One filled button per sheet**, the primary, as Android's `actions`. A secondary that previews (HEAR IT, LISTEN, TRY IT) does not close the sheet.
- **Every way out that is not a button does what CANCEL does** (the dim, a swipe down, the escape gesture): nothing is saved, and what the sheet started (a preview, the live heart-rate connection, a scan) stops.
- The accessibility identifiers `CindyTrackerUITests` uses keep working, or the test changes in the same commit.
- **UI-test lessons from U2 to U4:** find a control by an identifier or its exact label, never a fragment another control shares; the Cindy sheet's two buttons have the identifiers `sheetPrimary` and `sheetSecondary`, and a button with an identifier is not found by its label alone (`sheetButton`); a covered page stays in XCUITest's queries; a button at the foot of a scroll view needs scrolling to; `-attempts ""` and `-display_name ""` shadow stored values for one launch only, and a value written in that launch is not read back; a bare trailing closure whose body is an `if` can be taken for an overload's `onDismiss`, so name `content:`; `Text("\(int)")` groups digits, use `Text(verbatim:)`; `swiftc -parse` does not catch a redeclaration or a type error, so re-read every edit; a UI test that types into a field must not leave a name or weight another test reads.

- **Parse the app.** `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble sh -c 'for f in ios/CindyTracker/*.swift ios/CindyTrackerUITests/*.swift; do swiftc -parse $f || echo FAIL $f; done'`. Syntax only.
- **App tests.** Open the pull request as a draft after Task 1 and read `Build and test the app (macOS)` after pushes; a run takes about 26 minutes and a later push cancels it, so push once per batch of tasks. Its log lists every failed UI test; the run's `ios-captures` artifact holds the PNGs (`gh run download <id> -n ios-captures`).

## Review Focus

- **The keyboard over a sheet.** The body-weight, heart-rate-details and name fields stay visible above the keyboard together with SAVE. Test in Task 2.
- **The largest Dynamic Type size.** The voice sheet (a field-less but long list) keeps its primary reachable at `accessibility-XXXL`: the content scrolls inside 60% of the height and the buttons stack. Test in Task 3.
- **A dismissal that is not a button.** The dim, a swipe down and the escape gesture on the voice, movements, reminder and heart-rate sheets save nothing and stop what the sheet started (the speaker goes back, the audition stops, the live connection and the scan end). Test in Tasks 2, 3 and 5.
- **A refused entry.** SAVE with a weight of 5 keeps the sheet open with the model's message under the field, where Android closes the sheet and loses what was typed. Test in Task 2.
- **A sheet over a sheet's own work.** The heart-rate flow moves between its panels (the main one, the scan, "Your details") inside one presented sheet, and a refused notification permission replaces the reminder sheet with its own. Neither leaves the menu's page below it reachable by VoiceOver. Owed on a phone.

```swift
public enum SheetWords {
    public static let save = "SAVE", cancel = "CANCEL", done = "DONE", notNow = "NOT NOW"
    public static let hearIt = "HEAR IT", forget = "FORGET", openSettings = "OPEN SETTINGS"
    public static let language = "LANGUAGE", volume = "Volume"
}
// SheetButton gains `var keepsOpen: () -> Bool = { false }`, read after the action runs: true leaves the sheet up.
struct CindyPanel<Content: View>: View {
    init(title: String, subtitle: String? = nil, primary: SheetButton, secondary: SheetButton? = nil,
         secondaryDismisses: Bool = true, @ViewBuilder content: () -> Content)
}
extension EnvironmentValues { var closeCindySheet: () -> Void }   // set by the presenter
extension View {
    func cindySheet<Item: Identifiable, Panel: View>(item: Binding<Item?>, onDismiss: @escaping () -> Void = {},
                                                    @ViewBuilder panel: @escaping (Item) -> Panel) -> some View
}
struct SheetNote: View { init(_ text: String) }                       // .footnote, padding 8 above, 4 below
struct SheetChoiceGroup<T: Hashable>: View {                           // Dialogs.kt choiceGroup
    init(_ title: String, options: [T], selected: Binding<T?>, label: (T) -> String,
         note: (T) -> String?, spoken: ((T) -> String?)? = nil)
}
struct SheetField: View {                                              // the glass text field of askBodyWeight / askName
    init(_ hint: String, text: Binding<String>, keyboard: UIKeyboardType, style: CindyType, focused: FocusState<Bool>.Binding)
}
```
