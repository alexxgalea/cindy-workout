# U3: Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use the `subagent-driven-development` skill (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the iPhone app's Progress screen has the Android screen's shape: a title and a line saying what it is, the cards in `RecordsActivity.kt`'s order built from the shared rows and glass cards, a trained day opening a Cindy sheet, a reopened session opening full-screen, and DONE pinned at the foot.

**Architecture:** the page's decisions already live in CindyCore (`ProgressPageBuilder`, `ProgressModel`, `ProgressChartModel`, `CalendarModel`, `WeekStripModel`), so this phase changes what SwiftUI draws and, where a word is drawn by the view and not held by the model, moves it into CindyCore with a test that reads it off the Kotlin. `ProgressScreen.swift` composes the page; its cards go in `ProgressCards.swift`; the three drawn views in `ProgressCharts.swift` are painted from the tokens.

**Tech Stack:** SwiftUI (iOS 17.0), CindyCore (XCTest on Linux), XCUITest with `-CindyReplay`.

**Spec:** `ios/ui-parity/PLAN.md` (decisions and global constraints) and `docs/adr/0003-ios-follows-android-ui.md`. The Android sources, read on `origin/main` at `82672a7`: `res/layout/activity_records.xml`, `RecordsActivity.kt` (`render`, `hero`, `streakColumn`, `thisWeek`, `tile`, `peaks`, `renderCalendar`, `openDay`, `monthArrow`, `renderProgress`, `progressNote`, `leaderboard`), `CalendarView.kt`, `WeekStripView.kt`, `ProgressChartView.kt`.

**One correction to the master plan.** Its U3 line says "chips, chart card, calendar, peaks, then the leaderboard". The Kotlin draws the hero, THIS WEEK, the PROGRESS chart card (with its chips inside it), PEAKS, the calendar, then the LEADERBOARD, and so does the iPhone page today. This phase keeps that order and corrects the sentence (Task 6).

## Global Constraints

Everything in the master plan's global constraints, in particular:
- iOS 17.0 is the floor. No blur, no system materials. Colours only from `Palette`, type only from `CindyType` and `Manrope`, icons only from `CindyIcon`.
- Words are copied verbatim from the Kotlin. Nothing in code or comments names a phase.
- **`Ink`, `Color.accent`, `Color.dim`, `Color.warn`, `Chip`, `PrimaryButton` and `GhostButton` stay defined.** Account, Avatar and the menu still read them. This phase stops using them in `ProgressScreen.swift` and `ProgressCharts.swift`.
- The models in CindyCore own the geometry, the touch and the words they build, and are not changed except for `ProgressWords`. The views paint what they say.
- The menu's presentation of Progress (a pushed destination in `MenuScreen`) is U4's and stays. The accessibility identifiers `CindyTrackerUITests` uses keep working.
- **UI-test lessons from U2:** find a control by an identifier or its exact label, never by a fragment another control shares; a covered page stays in XCUITest's queries, so choose the hittable one in code (a query predicate cannot use `isHittable`); a button at the foot of a scroll view exists but is not hittable until scrolled to; the simulator keeps the records earlier tests left unless the launch argument `-attempts ""` empties them for one launch.

## Verification commands

- **Core tests.** `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble swift test --package-path ios/CindyCore`, with `--filter <Class>` for one. If Docker is not running in a cloud session: `pkill -9 containerd; pkill -9 dockerd; rm -f /run/containerd/containerd.sock /var/run/docker.pid /var/run/docker.sock; dockerd &`.
- **Parse the app.** `docker run --rm -v "$PWD":/w -w /w swift:6.1.2-noble sh -c 'for f in ios/CindyTracker/*.swift ios/CindyTrackerUITests/*.swift; do swiftc -parse $f || echo FAIL $f; done'`. Syntax only.
- **App tests.** Open the pull request as a draft after Task 1 and read `Build and test the app (macOS)` after pushes; a run takes about 22 minutes and a later push cancels it. Its log lists every failed UI test with its assertion; `gh api repos/alexxgalea/cindy-workout/actions/artifacts/<id>/zip` downloads `ios-captures`.

## Review Focus

- **The largest Dynamic Type size.** At `accessibility-XXXL` the two streak figures (46 points beside a unit) do not overflow their columns, the chip rows still reach every chip, and DONE, which is pinned, stays on screen. Test in Task 3.
- **An empty board.** No THIS WEEK, PROGRESS, PEAKS or calendar, and no gap where they would be; the LEADERBOARD shows the benchmark row and the "No attempts yet" note. Test in Task 2.
- **One attempt.** The PROGRESS card needs two sessions (`attempts.size < 2` in the Kotlin); with one, THIS WEEK, PEAKS and the calendar still show. Pinned in CindyCore in Task 1, which already holds the page's sections.
- **A session reopened from a day or a leaderboard row.** DONE returns to Progress, not to the camera; DISCARD there says "Session discarded" under it, and the rows that listed it are gone. Test in Task 2.
- **A month arrow at the end of the history.** It is disabled and out of the accessibility tree, and paging months does not lose the chart's selected point. By construction (the model's `canGoBack`/`canGoForward` and `shown`); owed on a phone.
